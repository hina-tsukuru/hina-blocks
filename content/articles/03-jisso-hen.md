こんにちは、ひなです🐣

丸の内で働くOLです。スクリーンタイム1日9時間を治すために、自分をスマホからブロックするアプリを、エンジニアじゃないのにAI（Claude Code。以下「AIくん」）と作っています。

[前回](https://zenn.dev/hinac/articles/e6eb7df2d87db4)は、自分のiPhoneに `Hello, world!` を表示させるまでに4回止められた話でした。今回はいよいよ中身です。

そして——

## ブロックできました🎉

アプリを選んで、ボタンを押して、ホームに戻って、選んだアプリを開く。

**開きません。** ちゃんと塞がれています。

Xを開こうとして塞がれたとき、思ったより「うっ」ときました。自分で作って自分で掛けたのに。これ、効くやつです。

……で、ここまで来るのに、やっぱり色々ありました。

## 「動いた」は、証明になりませんでした

最初の関門はここでした。

このアプリの中核にあたる機能（Screen Time API）は、**年12,800円の有料プログラムに入っていないと使えません**。私は課金済みです。なので当然、使えるはずでした。

AIくんがビルドを走らせます。

```
** BUILD SUCCEEDED **
```

通りました。やった、有料の設定が効いてる——と、私は思ったんですが、AIくんがこう言い出しました。

> 「念のため、発行された証明書の中身を見ます」

見たら、こうでした。

```
作成: 9月13日
期限: 9月20日
```

**7日間。**

有料プログラムの証明書は1年有効です。7日なのは**無料の証明書**。つまり、課金前に作られた古い証明書がパソコンに残っていて、それをそのまま使い回していただけでした。

ビルドは通ります。通るけど、有料の機能は使えない。**「成功した」という事実が、確かめたいことの証明になっていなかった**わけです。

古いものを退避してやり直したら、今度はこうなりました。

```
作成: 9月19日
期限: 2027年9月19日
```

1年。これでやっと本物です。

### 学び：「動いた」で満足すると、何を確かめたかったのか見失う

私が確かめたかったのは「ビルドが通るか」ではなく「**有料の権限が効いているか**」でした。前者は通っても、後者の答えにはなっていなかった。

見分け方はすごく地味で、**証明書の有効期限が7日か1年か**、それだけです。こういうの、知らないと一生気づけないやつだと思います。

## AIくんが、正しい答えに、間違った理由で辿り着きました

次はこれです。実機にアプリを入れようとしたら、突っぱねられました。

```
The developer disk image could not be mounted on this device.
```

AIくんが調べて、こう言いました。

> 「iPhoneのiOSが、Xcode（開発ツール）より新しいためです。このフォルダを見ると、古いバージョンまでしか入っていません」

なるほど、と思って Xcode を更新したら、**直りました**。めでたしめでたし。

……の、数日後。私がふと「そのフォルダって何でしたっけ?」と聞いたんです。深い意味はなくて、ただ忘れただけです。

そしたらAIくんが実物を見に行って、こう言いました。

> 「すみません、**あのとき挙げた根拠は間違っていました**」

そのフォルダの中身は、アプリが落ちたときのログを読むための「翻訳表」で、実機で動かすための部品とは**別物**だったそうです。

結論（Xcodeが古いと実機で動かせない）は合っていた。対処（更新する）も合っていた。**根拠だけが間違っていた。**

### 学び：うまくいくと、理由は検証されないまま残る

これ、けっこう怖いなと思いました。だって**対処が当たってしまった**から。直った時点で誰も振り返らないし、間違った根拠だけが「そういうもの」として私の中に残るところでした。

しかも気づいたきっかけは、技術的な検証じゃなくて「**それ何でしたっけ**」という素人質問です。分かってない側にも、できることはあるらしい。

## 自分で作ったアプリに、閉じ込められかけました

ここがいちばん、作っててゾッとしたところです。

このアプリ、ざっくり言うと2ステップで動きます。

1. ブロックする対象（アプリやカテゴリ）を選ぶ
2. 「ブロックを開始する」を押す

で、最初にAIくんが書いてきた設計だと、**対象が選ばれていないとボタンが押せない**ようになっていました。何も選ばずに「ブロック中」になっても意味がないので、まあ妥当です。

でもこれ、よく見ると問題があって。

**ブロック中に、対象の選択が空っぽになったら?**

ボタンは「対象が無いから」押せません。でもブロックは掛かったままです。つまり——

**自分で掛けたブロックを、自分で解除できなくなります。**

スマホ依存を直すアプリが、ユーザーをスマホから閉め出したまま出られなくする。笑い話にもならないです。

なので、こういうルールにしました。

- ブロック**していない**とき → 対象が無ければ開始できない
- ブロック**中**のとき → 対象が何であろうと、**必ず解除できる**

そしてこの「必ず解除できる」の部分だけ、単独のテストにしてあります。将来うっかり壊したときに、テストが落ちて教えてくれるように。

### 学び：テストで守るべきものは、機能とは限らない

テストって「ちゃんと動くか」を確かめるものだと思ってたんですが、今回守ったのは「**閉じ込められないこと**」でした。機能というより、安全性です。

ブロッカーアプリって、ユーザーを不便にするのが仕事じゃないですか。だからこそ「**逃げ道だけは絶対に塞がない**」のが要るんだなと。作ってみるまで分かりませんでした。

## テストできないものが、けっこうあります

あと地味に困ったのがこれです。今回のアプリ、**自動テストで確かめられない部分がかなりあります**。

- スクリーンタイムの機能は、**シミュレータ（パソコン上の仮想iPhone）では動かない**。実機が要る
- 「どのアプリを選んだか」の情報は、**iPhoneの選択画面からしか作れない**。テスト用に偽物を用意できない

ちなみに、アプリ側は**ユーザーが選んだアプリの名前すら受け取れません**。プライバシーのための仕組みらしいのですが、おかげで画面には「アプリ 3件」みたいに**件数しか出せません**。

「Instagramをブロック中」とは表示できないんです。これ、私が最初「バグですか?」って聞いたやつです。仕様でした。

なので、テストの範囲をこう割り切りました。

- **自動テストで守る**: 件数から表示を組み立てる部分、保存して読み戻す部分、そして例の「必ず解除できる」
- **人間が実機で見る**: 許可ダイアログが出るか、本当にアプリが塞がれるか

全部テストできないなら、**どこを機械に任せてどこを目で見るか**を決める。それ自体が作業なんだなと思いました。

## おまけ：使い道のない作業を、2時間ぶんやりかけました

最後に、いちばん自分に刺さった話を。

計画表（WBS）に「実機での結合動作確認・**録画**」という項目がありました。Phase 2 の最後の作業です。AIくんはそれをそのまま持ってきて、私に「録画してください」と言いました。撮影時の注意まで丁寧に添えて。

で、私、聞いたんです。

**「それ、何のためにやるんですか?」**

本当にただ分かってなかっただけです。深い意図はありません。

そしたらAIくんが調べ直して、こう言いました。

> 「やらなくていいです。私の説明が悪かったです」

理由はこうでした。

- 発信の方針には「**スクショ**を使う」とは書いてあるが、**動画を使う型がない**
- 動画を使いそうな箇所は「**これは全部あとでやる。今はやらない**」と明記されている
- そもそも**録画は合否を判定しないので、テストの役に立たない**。確認が成立するのは「操作して、期待どおりか見る」ところまで

つまり**使う予定が、どこにもなかった**。計画表に書いてあるというだけで、2時間ぶんの作業が発生しかけていました。

### 学び：「計画に書いてあるから」は、理由じゃない

自分で書いた計画って、それ自体が正しさの根拠みたいに見えてくるんですね。3週間前の自分が書いたメモなのに。

AIくんは計画に忠実でした。忠実だからこそ、**目的を確かめずに実行しようとした**。止めたのは、分かってない側の「何のためですか?」でした。

私はエンジニアじゃないので、技術的な良し悪しは判断できません。でも「**それ何のため?**」は聞けます。今のところ、これがいちばん役に立っている気がします。

## 次回予告

アプリとしては、もう動いています。自分のiPhoneで、ちゃんとXを塞いでくれます。

次は**自動化**の予定です。いまはコードを直すたびに手でテストを走らせているんですが、これを全部機械にやらせるらしい。CI/CDというやつです。

……と、ここまで書いて気づいたんですが、私まだ**このアプリでXをブロックしたまま生活したことがない**んですよね。作るのに夢中で。

次回までに一度、本気で使ってみます。たぶん一番つらいのはそこです。
