こんにちは、ひなです🐣

丸の内で働くOLです。スクリーンタイム1日9時間を治すために、自分をスマホからブロックするアプリを、エンジニアじゃないのにAI（Claude Code。以下「AIくん」）と作っています。

[前回](https://zenn.dev/hinac/articles/32cdce0707fb9c)は「作ります」と宣言しただけでした。今回は環境構築編です。

そして——

## 動きました🎉

自分のiPhoneに、自分のアプリが入りました。

画面には `Hello, world!` と出ているだけです。ボタンもありません。何もできません。

でもこれ、**私（が指示してAIくん）が作ったアプリ**なんですよ。8日目にして、ようやくスタートラインに立ちました。

……と、いい話で終わればよかったんですが。

## ここに至るまでに、4回止められました

「アプリを作る」より「**自分の電話に入れる**」方が大変でした。順番に4回、iPhoneに拒否されています。

### 関門1：ケーブルを挿しても認識されない

iPhoneをMacに繋いで「このコンピュータを信頼しますか?」→ 信頼、を押しました。当然つながったと思うじゃないですか。

```
error: ... is not available because it is unpaired.
```

**まだペアリングされていません。** 「コンピュータを信頼」と「開発用のペアリング」は別物でした。1つ目の壁。

### 関門2：「デベロッパモード」が、そもそも画面に無い

調べると、iOS 16以降は**iPhone側で「私は開発者です」と宣言する設定**が必要らしい。

```
設定 → プライバシーとセキュリティ → デベロッパモード
```

無い。**その項目が存在しない。**

「設定」を隅から隅まで探しました。無いものは無い。10分ほど彷徨いました。

正解は「**一度Macから接続を試みると、その項目が出現する**」でした。**存在を知っていても、条件を満たすまで出てこない。** 探しても見つからないわけです。

しかも有効にすると**iPhoneの再起動が必要**でした。再起動って。

### 関門3：ビルドはできる。でもデバイスが登録されていない

再起動して、いざビルド。

```
error: Provisioning profile ... doesn't include the currently selected device
```

**プロビジョニングプロファイル。** また新しい呪文が出てきました。

AIくんに聞いたら「Appleに『このiPhoneで動かします』と事前登録が要る」とのこと。オプションを1つ足したら自動でやってくれました。

```bash
-allowProvisioningDeviceRegistration
```

長い。呪文が長い。

### 関門4：インストールは成功。でも起動しない

そして最後。アプリのインストールは**成功**しました。ホーム画面にアイコンも出ている。

タップしても、**起動しない。**

```
Unable to launch ... because its profile has not been explicitly trusted by the user
```

「**ユーザーがこのプロファイルを明示的に信頼していない**」。入れることはできたけど、開いていいとは言っていない、と。

```
設定 → 一般 → VPNとデバイス管理 → Apple ID → 信頼
```

これでやっと動きました。**4回目の許可**です。

## で、気づいたんですけど

この4つ、全部**わざと面倒にしてあります**。

- ペアリングを分けているのは、繋いだだけで中身を抜かれないため
- デベロッパモードを隠しているのは、知らない人が有効にしないため
- デバイス登録は、誰のiPhoneで動いているかをAppleが把握するため
- 起動前の信頼確認は、**入れられただけでは実行させない**ため

**バグではなく、設計です。** Appleは「不可能にする」のではなく「**面倒にする**」ことで安全性を作っている。

そしてこれ、私が今作ろうとしているアプリと**まったく同じ発想**でした。

## 競合を調べたら、自分の作ろうとしているものが分かった

AIくんに市場調査をしてもらいました。「同じようなアプリ、いくらで売ってるの?」と。

結果はけっこう厳しくて:

- **完全無料**のアプリが普通にある（サブスクなし・課金なし）
- 日本語対応のものも複数あって、1,500万ユーザー規模のものまである
- そもそも**iPhoneには標準で「スクリーンタイム」が無料で入っている**

じゃあなぜ、有料のアプリが売れているのか。

理由は**たった1つのボタン**でした。

iPhone標準のスクリーンタイムは、制限時間になっても「**制限を無視**」をワンタップ押せば使い続けられます。

> 夜11時の私は、画面から目を離さずにそのボタンを押す。

つまり標準機能は「**丁寧なお願い**」なんです。有料アプリはそこを埋めている。無視ボタンを消したり、解除に手順を挟んだり。

**「制限」ではなく「本気度の担保」を売っている。**

……気づきました? **さっきの4つの関門と同じ構造**です。破れなくするんじゃなくて、破るのを面倒にする。

私が作ろうとしているアプリの本質は「ロック」じゃなくて「**衝動と行動の間に隙間を作ること**」でした。作る前にそれが分かったのは、けっこう大きいです。

## AIくんが、堂々と嘘をつきました

今回いちばんの学びはこれです。

市場調査の途中で、AIくんがこう断言しました。

> サードパーティのアプリは、設定からトグルひとつで無効化できます。**原理的に完全なブロックは作れません。**

「へぇ〜、じゃあ意味ないじゃん」と思いつつ、念のため自分のiPhoneで確認したら——

**パスコード、要求されました。**

AIくんに突きつけたら、調べ直してこう返ってきました。

> **iOS 26.4 で修正されていました。** 参照した情報が iOS 18 時代のものでした。訂正します。

つまりAIくんは、**2年前の情報を、今の事実として断言していた**わけです。

これ、怖いのは「間違っていた」ことじゃなくて「**堂々としていた**」ことです。自信たっぷりに「原理的に不可能」と言われたら、普通は信じます。あのまま進んでいたら、**間違った前提でアプリを設計していました。**

### 学び：AIの「できません」は、日付を疑う

AIくんは基本的にはめちゃくちゃ優秀です。今日も4つの関門を全部解いてくれました。

でも**「仕様」や「制約」の話をするときだけは要注意**でした。技術の仕様は変わるのに、AIの知識は学習した時点で止まっているからです。

**実物を見られる人間の方が、その一点においては強い。** 非エンジニアの私でも、自分のiPhoneの設定画面は開けます。

これは今後も効きそうな教訓なので、AIくんへの指示書（`CLAUDE.md`）に書き足しました。

## おまけ：私の本名が3回漏れかけました

このプロジェクト、コードをGitHubで全部公開しています。で、匿名でやっているのに**本名が3回も混ざりかけました。**

1. AIくんへの指示書に、本名で運営している別サイトのURLを書いていた
2. **Xcodeが、作ったファイル全部に勝手に本名を書き込んでいた**（Macのアカウント名が自動で入る仕様）
3. 「本名が混ざってないかチェックするコマンド」を書いたら、**そのコマンド自体に本名を書いてしまった**

3番、笑えないです。**守るための仕組みが、守りたいものを晒していた。**

全部公開前に気づいて消しましたが、特に2番は自分では絶対に気づけませんでした。**自分が書いていない情報が、勝手に混ざる**ことがある。

## 次回予告

環境は整いました。実機でも動きます。次はいよいよ**ブロック機能の実装**……のはずでした。

が、ここで**年12,800円**の壁が立ちはだかっています。ブロック機能を使うには、Appleの有料プログラムへの加入が必須だと分かりました（これも無料で試せるところまで試して判明しました）。

無料で作れるアプリに、1万円超を払うか。

次回はそこから始めます。
