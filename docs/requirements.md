# MVP要件定義 — 集中支援アプリ（仮称 hina-blocks）

> WBS 0.1 の成果物。Confluenceと同期する（WBS 0.2）。
> 進捗ステータスは `docs/wbs.md`、全体像は `docs/agenda.md` を参照。
> 決定日: 2026-07-21 / バージョン: v1.0

## このアプリは何か

自分が選んだアプリを、集中したいときに開けなくする iOS アプリ。
作者自身（スクリーンタイム1日9時間）が、スマホ依存を自分で治すために使うのが第一目的。
Apple の Screen Time API（FamilyControls / ManagedSettings / DeviceActivity）で実装する。

## MVPのスコープ（最初のバージョンで作るもの）

「アプリを選んで、ボタンでブロックのON/OFFを切り替える」——これだけを確実に動かす。

### 0.1.1 ブロック対象：**アプリのみ**

- ユーザーが選んだ iOS アプリ（例: SNS、動画）を開けなくする
- Safari のサイトブロックは**MVPに含めない**（別Phaseで検討）
- カテゴリ単位での選択は FamilyActivityPicker が提供する範囲でそのまま使う

### 0.1.2 スケジュール方式：**手動オン・オフ**

- アプリ内のボタンでブロックを開始／解除する
- 時間帯の自動切り替え（毎日9〜18時など）は**MVPに含めない**
- ポモドーロ式（25分集中→5分休憩）も**MVPに含めない**
- → いずれも土台（手動ブロック）が動いてから、後のPhaseで足す

### 0.1.3 MVPに入れない機能（明示的に除外）

膨張を防ぐため、以下は最初のバージョンでは作らない。必要になったら後から足す。

| 除外する機能 | 理由 / 後回しの位置づけ |
|---|---|
| 使用時間の統計・レポート | ブロック本体とは別実装。まず本体を動かす |
| 解除にパスワード要求 | 意志の弱さ対策。あれば便利だが必須ではない |
| 複数プロファイル切替（仕事用/勉強用） | 便利機能。1プロファイルで十分に始められる |
| iCloud同期・ウィジェット・通知 | 周辺機能。単一端末・アプリ内完結で始める |

## 動作の流れ（MVPのユーザー体験）

1. アプリを開く
2. （初回）ブロック機能を使う許可をリクエストする ← FamilyControls
3. 「ブロックするアプリ」を選ぶ ← FamilyActivityPicker
4. 「ブロック開始」ボタンを押す → 選んだアプリが開けなくなる ← ManagedSettings
5. 「ブロック解除」ボタンを押す → 元に戻る

## 技術・設計上の制約（要件に効くもの）

- **アプリの具体名は取得できない**：Screen Time API は不透明トークン設計。「今ブロック中のアプリ一覧を名前で表示」はできない前提でUIを組む
- **シミュレータで動かない**：Family Controls は実機必須。ロジック部分のみ XCTest で担保
- **データを外部送信しない**：ユーザーの選択情報は端末内に閉じる。プライバシーポリシーにも明記予定（WBS 5.1）
- **開発用エンタイトルメントで進める**：配布時は別途 Apple へ申請（WBS 5.2）

## 未決定・保留（後日決める）

- ブロック中の見せ方（シールド画面の文言・デザイン）は実装時に詰める
- MVPの次に何を足すか（時間帯指定 / パスワード / 統計のどれを優先するか）は、2週間のドッグフーディング（WBS 4.1）の結果で決める
