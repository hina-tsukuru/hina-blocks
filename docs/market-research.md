## 結論（3行）

1. **完全無料のアプリは存在する**（ScreenZen。サブスクなし・課金なし・全機能開放）
2. それでも有料アプリが成立しているのは、**iOS標準スクリーンタイムに「Ignore Limit」という致命的な穴がある**から
3. サードパーティ側にあった「権限をトグルでオフにできる」穴は **iOS 26.4 で塞がれた**（パスコード必須になった）
4. ただし**自分用だと自分がパスコードを知っている**。だからこのジャンルの本質は「ロック」ではなく
   **「破るコストを、衝動が続く時間より長くする」コミットメント装置**の設計にある

## なぜ無料のOS標準機能があるのに、有料アプリが売れるのか

### 「Ignore Limit」ボタン問題

iOS標準のスクリーンタイムは、制限時間に達しても **「制限を無視」ボタンをワンタップ押せば使い続けられる**。

> 自分の意志を管理したい人にとって、これは**設計上の致命的欠陥**。
> 夜11時の自分は、フィードから目を離さずにこのボタンを押す。

つまり標準機能は「**丁寧なお願い**」であって強制力がない。有料アプリはここを埋めている:

- 「無視」ボタンを取り除く
- アンインストール・強制終了・時刻変更などの回避手段に耐える
- 解除に摩擦（遅延・入力・パスワード）を挟む

**「制限」ではなく「本気度の担保」を売っている**と言える。

### ScreenZen（無料）のアプローチ

ブロックではなく**遅延を挟む**方式。アプリを開くと一度停止画面が出て、「本当に開くか」を確認させる。1日の起動回数に上限も設定できる。

「意志を強制する」のではなく「衝動と行動の間に隙間を作る」という設計。これを無料で提供している。

## サードパーティアプリの弱点は、iOS 26.4 で塞がれた

### かつての穴（iOS 26.3 以前）

- iOSの設定から、サードパーティアプリのスクリーンタイム権限を**トグルひとつでオフにできた**
- スクリーンタイムにパスコードをかけていても、**この操作だけはパスコードが要求されなかった**（Face IDや端末PINで通った）
- 開発者フォーラムで「数万人の要望第1位」と言われ、iOS 16 の頃から報告されていた

### 現在（iOS 26.4 以降）

**修正済み。** 「スクリーンタイムにアクセスできるApp」の権限をオフにする際、
**スクリーンタイムのパスコードが要求される**ようになった。

> ⚠️ **調査時の教訓**: 最初に見つけた情報源は iOS 18 時代のもので、
> 「サードパーティには原理的に完全なロックは作れない」と結論づけてしまった。
> 実機を確認した結果、既に修正されていた。
> **APIやOSの制約を調べるときは、情報の日付を必ず確認する。**

### 残る問題：自分用だとパスコードを自分が知っている

パスコード保護は「**設定した人と使う人が違う**」場合に効く（親と子）。

自分で自分を止める用途では、**自分がパスコードを知っている**ため、
入力すれば解除できてしまう。

ただし摩擦は大きく上がった:

```
旧: 設定 → トグルをオフ（3タップ）
新: 設定 → スクリーンタイム → パスコード入力 → 該当アプリ → オフ
```

「衝動的にワンタップ」ができなくなった点は大きい。

---

## 本質：これは「ロック」ではなく「コミットメント装置」

自分で自分を止めるアプリの本質的な課題は、**未来の自分が抜け道を知っている**こと。
これはこのジャンル全体の前提であり、解決策は「破れなくする」ことではなく
「**破るコストを、衝動が続く時間より長くする**」ことにある。

衝動は数分で過ぎる。だから**数分耐えられれば勝ち**という設計になる。

### 知っていても効く仕掛け

| 仕掛け | 効く理由 |
|---|---|
| **解除に時間差を入れる**（「15分後に解除されます」） | 衝動のピークを過ぎさせる。最も効果が高い |
| **解除の理由を書かせる** | 言語化させると、衝動的な行動は続きにくい |
| **解除履歴を可視化する** | 後から見ると気まずい。回数自体が抑止になる |
| **パスコードを自分で覚えない** | ランダム値を紙に書いて別の部屋・封筒に置く |
| **他人に設定してもらう** | パートナー・友人に入力してもらう。最も堅いが人に頼る必要がある |
| **解除を誰かに通知する** | 社会的な監視。ひとりで完結しない |

**「意志の代わり」にはならないが、「意志が切れる瞬間」を乗り切らせることはできる。**

これが、標準スクリーンタイムがあるのに有料アプリが売れている理由の中核でもある。

**ScreenZen は日本のApp Storeでも配信されている**（`apps.apple.com/jp/app/...id1541027222`）。

つまり **「無料の強力な競合」は日本市場にも存在する。**
言語の壁がある分だけ発見されにくいが、口コミで広がりつつある。

### 日本語圏でよく読まれているのは「抜け道」の話

検索結果の上位に「**iPhoneのスクリーンタイム抜け道 完全ガイド｜制限解除ワザとアプリ別対策**」
のような記事が入ってくる。

これは需要の裏返しで、**「制限をかけたい側」と「破りたい側」が同じ人**という構図を示している。
前述の「Ignore Limit問題」と同じ話が、日本語圏でも中心的な関心になっている。

## Screen Time API の設計上の制約（実装に効く）

- **不透明トークン設計**: `FamilyActivitySelection` で選ばれたアプリの情報は暗号化トークンで隠され、アプリ側は「どのアプリが選ばれたか」を一切知れない。プライバシー優先の設計
- **Family Controls はアプリ自体の削除を防げる**（ペアレンタルコントロール用途）
- 権限のオフは、iOS 26.4 以降は**スクリーンタイムのパスコードで守れる**（前述）

## このプロジェクトへの示唆

### 1. 収益化は期待しない方がよい

**完全無料で高機能な競合（ScreenZen）がいる時点で、有料で売るのは相当に厳しい。**
市場は成熟していて、無料〜年1万円まで選択肢が揃っている。後発が価格で戦う余地は薄い。

### 2. だからこそ12,800円の判断は単純になる

このプロジェクトの目的は [requirements.md](requirements.md) のとおり:

> 作者自身（スクリーンタイム1日9時間）が、**スマホ依存を自分で治すために使うのが第一目的**

加えて「AI駆動開発・DevOpsの学習」と「発信」。つまり **12,800円は事業投資ではなく、学習と発信のコスト**。

「回収できるか」ではなく「**1年間の学習教材＋記事ネタとして12,800円は妥当か**」で判断すればよい。
（比較: 技術書3冊、オンライン講座1本ぶん）

### 3. 差別化の余地は「摩擦の設計」にある

機能では勝てない（AppBlock 1,500万ユーザー、ScreenZen 無料）。
だが**「知っていても効く仕掛け」を丁寧に作っているアプリは意外と少ない**。

特に **解除の時間差**（「解除は15分後」）は、実装が軽いわりに効果が大きい。
衝動が数分で過ぎることを利用する仕掛けで、意志力を要求しない。

ここは MVP の次に検討する価値がある。

### 4. MVPの設計に再考の余地がある

調査で分かった「有料アプリの存在理由 = **Ignore Limitを潰すこと**」に対し、
現在のMVP要件は **「ボタンで手動オンオフ」**（[requirements.md](requirements.md) 0.1.2）。

これは**自分でいつでも解除できる**設計であり、
標準スクリーンタイムの「Ignore Limit」と同じ弱さを持つ。

- MVPとして「まず動かす」ことを優先した判断なので、**現時点では正しい**
- ただし Phase 4 のドッグフーディングで「結局すぐ解除してしまう」問題が出る可能性が**極めて高い**
- **むしろ、それを観測すること自体が Phase 4 の目的**にできる。
  「作った当日に自分で解除した」なら、それは失敗ではなく最良の観測結果であり記事ネタでもある
- その結果を見てから「解除に摩擦を入れる」（現在は除外リスト入り）を再検討する
