# docs/roi-checklist.md — 新しいアプリを作る前に通す確認

作成: 2026-09-09

## なぜこれがあるか

このプロジェクトでは、市場調査（WBS 0.10）を**12,800円を払う判断の直前**にやった。
その結果「収益化は現実的でない」と分かったが、それはもっと早く分かるべきことだった。
順序が逆だったので、次からは着手前に通す。

**所要時間の目安は合計1時間。** 完璧な分析ではなく、「1時間だけ現実を見る」ためのもの。

## 使い方

新しいアプリを始めるとき、この項目をコピーして埋める。

**埋まらない項目があってもよい。ただし空欄にせず「分からなかった」と書く。**
埋まらなかったこと自体が情報になる（＝そこがリスク）。

---

## 1. 誰の、何を解決するか（15分）

- [ ] 困っている人は具体的に誰か（「みんな」は不可。1人思い浮かべる）
- [ ] その人はいま何で代用しているか — **これが本当の競合**。他社アプリとは限らない（手帳、我慢、諦め）
- [ ] 代用をやめてまで乗り換える理由は何か

## 2. 競合（20分）

- [ ] 同カテゴリの上位5本を挙げる: 名前 / 価格 / DL規模 / 評価
- [ ] **無料で十分よくできたものが既にあるか** — あるなら、収益化は諦める前提で以降を書く
- [ ] OS標準機能で足りてしまわないか

## 3. お金（10分）

- [ ] 出ていく金額（初期 / 継続）— 例: Apple Developer Program 12,800円/年
- [ ] 入ってくる見込み: 買い切り / サブスク / 広告 / なし
- [ ] **回収できない場合、その支出を何と呼ぶか** — 学習費 / コンテンツ費 / 趣味

> 3つ目が一番大事。ここを言語化しないと、後から「損した」という感情だけが残る。
> 「学習費だ」と先に決めておけば、回収できなくても計画通りになる。

## 4. 何のために作るのか（5分）

- [ ] 収益 / 実績・信頼 / 学習 / 自分が使いたい — から選ぶ
- [ ] **複数選ばない。** 選んだものによってKPIも打ち手も変わるので、混ぜると判断できなくなる

## 5. どう届けるか（10分）

- [ ] 届けたい相手はどこにいるか（App Store検索 / SNS / 既存の読者 / 口コミ）
- [ ] **発信の読者と、アプリの利用者は同じ人か？**
      違うなら、それぞれのルートを1行ずつ書く（片方しか書けないなら、もう片方は諦めると決める）
- [ ] 集客手段が思いつかないなら、「作った後に考える」にせず**いま決める**

## 6. やめる条件（5分）

- [ ] 何が起きたら畳むか（例: リリース後3ヶ月でDLが2桁）
