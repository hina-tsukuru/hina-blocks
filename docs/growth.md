# docs/growth.md — このアプリをどう広めるか

作成: 2026-09-09

## この文書の位置づけ

「作った後に考える」を避けるために、実装に入る前に広め方を決めておく。
方針そのものより、**何を期待しないと決めたか**を残すことを重視している。

---

## 前提となる2つの決定

### 決定1: いまユーザーを増やす目的は「実績・信頼」。収益は当面の目的にしない

**注意: 「このカテゴリでは稼げないから」ではない。** その理解は誤りだった（`docs/market-research.md` の訂正を参照）。
実際には AppBlock は $29.99/年、Opal は $99.99/年 で成立している。

収益を当面の目的から外すのは、次の2つの理由による。

1. **基本のブロック機能では課金できない。** ScreenZen が 4.8★ で完全無料配布しており、価格の錨がゼロにある。
   課金が成立しているのは複数プロファイル / スケジュール / 統計 / 同期など、**現MVPが意図的に除外している領域**
2. **収益は配布の後にしか来ない。** AppBlock は1,500万ユーザーがいるから月額が成立している。
   ユーザーゼロの状態で収益を目的に置くと、MVPの設計が「課金できる機能」に引っぱられて歪む

つまり収益化は「無理だから諦める」のではなく、**判断の順番として後**に置く。
`docs/roi-checklist.md` の「4. 何のために作るのか（複数選ばない）」に従い、いまは実績・信頼に一本化する。

### 決定2: 記事の読者と、アプリの利用者は別人。分離したまま運用する

- **記事の読者** = AI駆動開発に興味のある作り手。知りたいのは「どう作ったか」
- **アプリの利用者** = スマホを見すぎて困っている人。知りたいのは「どう自分を止めるか」

この2つは重ならない。重ねるには、アプリを「開発者向け集中アプリ」に作り替える必要があるが、
**発信の都合で製品を歪めない**という判断で、分離したまま運用する。

---

## この2つから自動的に決まること

### ① 記事はアプリの集客手段として数えない

記事を何本書いてもダウンロードは増えない前提で計画する。
アプリを広める仕事は、すべて App Store 側（ASO）に寄る。

> これを混ぜると「DLが伸びない → 記事が足りないのでは」という**誤った打ち手**に迷い込む。
> 原因の切り分けができなくなるので、最初から分けておく。

### ② ユーザー数の最大化はKPIから降りる

信頼という観点では、この2つの差はほとんどない。

- 100人が使っている / 10,000人が使っている

一方、この2つの差は決定的。

- **App Storeに存在する / 存在しない**

つまり **「リリースまで到達すること」自体が最大の成果**。DL数は二次指標。

### ③ Apple Developer Program の12,800円（KAN-19）は「Yes」に倒れる

実績とは「他人が検証できる形で存在すること」。
自分用・TestFlight止まりでは、記事を何本書いても実績資産はゼロになる。

したがって12,800円は「回収できるか」を検討する投資ではなく、**実績を作るための参加費**。
`docs/market-research.md`「2. 12,800円は「回収」で判断しない」と同じ結論に、別の道筋で着いた。

## 2つのレーン

| | レーンA: 発信 | レーンB: アプリ |
|---|---|---|
| 相手 | AI開発に興味のある作り手 | スマホを見すぎて困っている人 |
| 目的 | ヒナの信頼を積む | 実際に使われる |
| 場所 | X / Zenn / GitHub | App Store のみ |
| 主な指標 | 公開した記事数、Xの反応 | DL数、レビュー、継続率 |
| 手段 | 既存の週次サイクル（`docs/character.md`） | ASO（下記） |
| いま動いているか | **動いている** | **Phase 5 まで動かない** |

### 2つが交わる唯一の点

記事の末尾に App Store リンクを置く。コストはゼロなので置く。
**ただし集客見込みはゼロで計上する。** 効いたらボーナス扱いにする。

---

## レーンB（アプリ）の手段 — App Store内で完結させる

ASO = App Store Optimization。App Store の検索結果で見つけてもらうための調整。
中身は4つしかない。

1. **アプリ名とサブタイトル** — 検索される言葉を入れる（例:「集中」「スクリーンタイム」「制限」）
2. **スクリーンショットの1枚目** — 見るかどうかはここでほぼ決まる
3. **キーワード欄** — 100文字。ユーザーには見えないが検索に効く
4. **初期レビュー** — 数件でも入口の印象が変わる

**ただし、これは全部 Phase 5（配布判断）以降の作業。いまやることはない。**
先回りして手をつけない。

---

## やらないこと

明示しておかないと、なんとなく手を出して時間を溶かすため。

- ❌ アプリを「開発者向け集中アプリ」に作り替える — 製品を発信の都合で歪めない（決定2）
- ❌ 消費者向けの第2チャネル（TikTok / Instagram）を作る — 運用が2本になる。**将来の選択肢としては残す**
- ❌ 有料化・課金設計を**いま**考える — 収益化は「無理」ではなく「順番が後」（決定1）。
  ユーザー基盤ができてから判断する。いま考えるとMVPの設計が歪む
- ❌ ダウンロード数を目標に置く — 目的が実績である以上、追っても目的に効かない

## この方針を見直す条件

方針は「捨て方」を書いておかないと惰性で続く。以下が起きたら書き直す。

| 起きたこと | 見直す内容 |
|---|---|
| リリース後3ヶ月でDLが2桁 | レーンBの手段が足りていない。第2チャネルを再検討する |
| 記事経由のDLが実際に多かった | 決定2（分離）の前提が誤り。統合を検討する |
| ユーザー基盤ができ、収益化を判断する段階になった | 決定1を見直す。**課金するなら現MVPの外側**（プロファイル / スケジュール / 統計 / 同期）が候補 |
