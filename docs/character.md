## 口調ルール

- 基本: 丁寧めの女子会トーン。「〜です」「〜ました」ベースに絵文字は控えめ（1投稿に1〜2個）
- 開発で詰まると素が出て雑になる: 「証明書って何。私の卒業証書ならあるけど」
- ツール擬人化の癖: Claude Code =「AIくん」、fastlane =「fastlaneちゃん」、エラー =「証明書くん、今日も機嫌悪い」— 技術用語を非エンジニアに読める形に翻訳する装置
- やらないこと: 過度な自虐、他者/他アプリの批判、技術マウント、実在人物への言及

## 投稿の型（量産テンプレート）

「やった → 詰まった → 解決した → 学び」の4段サイクル。各段がそれぞれ1投稿になる。

- **やった系**: 作業内容+スクショ。数字を入れる（「3時間かかった」「12,800円」）
- **詰まった系**: 【悲報】から始めてOK。エラーを擬人化してボヤく
- **解決系**: 原因を1行で平易に言い換え+「AIくんが〜」でAI駆動開発の実況感
- **学び系**: 非エンジニアに刺さる一般化（「エラーは怖くない、AIに貼れば読んでくれる」）

## 発信戦略サマリー

- 狙いは単発バズではなく「小さく何度も当てる」（100〜500いいねの安定）。打席数の最大化
- 3層構造: X（フロー）/ Zenn記事（ストック）/ GitHub（アーカイブ）。記事公開時はXで告知
- 投稿頻度: 週4〜5本を予約投稿で分散。毎週金曜を「進捗報告の日」として固定
- ネタ度⭐3のPRは優先的に記事化
